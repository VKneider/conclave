# Data format & lifecycle

## Storage

All data persists in `localStorage`. No server-side persistence — the app is fully frontend-only.

| Key | Content | Owner |
|---|---|---|
| `conclave-teams-v1` | `Team[]` JSON | `RosterService._saveToStorage()` |
| `conclave-members-v1` | `Member[]` JSON | `RosterService._saveToStorage()` |
| `conclave-assignment-v1` | `{[memberId]: teamId}` | `assignment` context (persist: true) |
| `conclave-resolutions-v1` | `{[memberId]: teamId}` | `resolutions` context (persist: true) |
| `conclave-settings-v1` | `{autor, nombreOrganizacion, lideres, lideresEnabled}` | `settings` context (persist: true) |

## CSV format (HelpView)

### Teams

Header: `id,nombre,min,max,capacidad,lider,asignable`

```
id,nombre,min,max,capacidad,lider,asignable
transporte,Transporte,4,6,6,,true
banda-en-vivo,Banda en Vivo,6,10,10,,true
```

- `id`: slug-like identifier (e.g., `transporte`). Autogenerated from nombre if omitted.
- `nombre`: display name (can be quoted if it contains commas).
- `min` / `max`: minimum and maximum members.
- `capacidad`: absolute capacity (may differ from max).
- `lider`: name of the leader (string, optional). If set, `isLiderLocked()` returns true.
- `asignable`: `true` or `false`. Non-assignable teams are excluded from assignment views.

### Members

Header: `id,nombre,sexo,edad,rolFijo,fijo`

```
id,nombre,sexo,edad,rolFijo,fijo
1,Juan Pérez,M,25,,false
2,María García,F,30,,false
```

- `id`: numeric (e.g., `1`, `2`). Autogenerated incrementally if omitted.
- `nombre`: display name.
- `sexo`: `M` or `F` (single letter).
- `edad`: number.
- `rolFijo`: fixed role string (optional).
- `fijo`: `true` or `false`. Fixed members are excluded from assignable lists.

## Fixed ID strategy

The first column in both CSV formats is `id`. This ID is the stable identifier that assignments, resolutions, leaders, and imported sources use to reference a specific entity.

- **Substituting a person/team**: Change nombre/data but keep the same ID. All references survive.
- **Deleting**: Remove the row. On save, orphaned references (assignments, resolutions, settings.lideres, ImportService sources) are automatically cleaned up by `RosterService._cleanupOrphaned()`.
- **Adding**: Add a row. If ID is omitted, it's autogenerated (slug from nombre for teams, incremental number for members).
- **Renaming a team**: Change nombre, keep ID. Assignments to the team are preserved.

## Data flow on replacement

See ARCHITECTURE.md §Roster replacement for the full flow. Key cleanup steps:

1. `_cleanupOrphaned()` iterates `assignment` context, removes entries where memberId or teamId no longer exists.
2. Same for `resolutions` context.
3. Same for `settings.lideres` (leader assignments pointing to deleted members).
4. Same for `ImportService` sources (removes orphaned member/team references from comparison data).
